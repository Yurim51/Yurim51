# 매매 규칙 설계 v0.1 — 미국 주식 스윙

확정된 전제:

| 항목 | 결정 |
|------|------|
| 시장 | 미국 먼저 → 안정화 후 국내 확장 |
| 스타일 | 스윙 (보유 수일~수주) |
| 종목 선정 | Track A(고정 관심종목) + Track B(조건 스크리닝) 병행, 성적 비교 |
| 1회 리스크 | 자본의 1% (= 1R) |
| 목표 | 연 +80% |

---

## 0. 목표의 해석 — 연 80%가 규칙에 요구하는 것

1회 리스크를 1R(=자본의 1%)로 고정하면, 연 80%는 **연간 순 +80R**을 의미한다.
기대값(expectancy)과 거래 횟수로 분해하면:

| 승률 | 평균 손익비 (익절R : 손절R) | 기대값/거래 | 연 80R에 필요한 거래 수 |
|------|------|------|------|
| 40% | 3.0 : 1 | +0.60R | 약 133회 (주 2.6회) |
| 45% | 2.5 : 1 | +0.58R | 약 139회 (주 2.7회) |
| 50% | 2.0 : 1 | +0.50R | 160회 (주 3.1회) |
| 35% | 3.0 : 1 | +0.40R | 200회 (주 3.8회) |

**정직한 체크포인트**: 기대값 +0.4~0.6R을 수백 회 거래에서 유지하는 것은 전업 트레이더 기준으로도 최상위 성과다. 그래서 이 문서의 규칙은 80%를 "보장"하는 게 아니라, 80%가 수학적으로 가능해지는 **비대칭 구조**(손실은 1R에서 기계적으로 자르고, 이익은 2R 이상으로 키우는)를 강제하는 데 집중한다. 성공/실패 판정은 수익률이 아니라 **측정된 기대값**(§7)으로 한다 — 기대값이 양수인데 거래 수가 부족한 것과, 기대값 자체가 음수인 것은 처방이 완전히 다르기 때문이다.

## 1. 유니버스 (종목 선정)

### Track A — 고정 관심종목 (MVP)
- 10~15개, 편입 기준: ① 일평균 거래대금 상위(유동성) ② 시총 $10B+ ③ 본인이 사업을 이해하는 종목
- 구성 균형: 메가테크 4~5 + 반도체/AI 2~3 + 지수 ETF 1~2(QQQ/SPY) + 기타 섹터 3~4
- 분기 1회만 교체 (수시 교체 금지 — 규칙 검증이 안 됨)

### Track B — 조건 스크리닝 (Phase 3 후반부터)
- 매일 EOD 배치로 후보 추출: 20일 신고가 근접(고가 대비 -3% 이내) + 거래량 증가(20일 평균 대비 1.5배+) + 최소 주가 $10 + 재무등급 C 이상(DART 연동 전엔 생략)
- 후보 상위 20개만 다음날 감시 대상에 편입

### 비교 방법
- 모든 거래 기록에 `track: A|B` 태그 → 기대값·승률·손익비를 트랙별로 분리 집계
- 같은 종목이 양쪽에서 신호 나면 A로 귀속 (중복 진입 금지)

## 2. 진입 규칙

### 공통 필터 (하나라도 걸리면 신규 진입 금지)
- **시장 국면 필터**: SPY 종가가 50일 SMA 아래면 신규 매수 없음 (하락장에서 롱 스윙의 기대값은 급락함)
- **실적발표 필터**: 실적발표 D-3 ~ D+1 진입 금지 (갭 리스크는 손절로 못 막음)
- 동시 보유 한도 초과 시 진입 금지 (§5)
- 당일 신규 진입 최대 2건 (신호가 많아도 우선순위 상위 2건만)

### E1 — 추세 눌림목 (pullback)
> 상승 추세 종목이 단기 조정 후 재반등하는 지점 매수. 승률형 규칙.

- 조건 (일봉, 전일 종가 기준):
  1. 종가 > 50일 SMA 그리고 50일 SMA 상승 중 (추세 확인)
  2. 종가가 20일 SMA의 ±2% 이내로 조정됨 (눌림)
  3. RSI(14) 35~55 구간 (과매도 직전까지 눌렸다가)
  4. **트리거**: 당일 가격이 전일 고가 돌파 (반등 확인)
- 진입: 트리거 시 지정가(전일 고가 + 0.1%)
- 초기 손절: `min(최근 10일 스윙 저점 − 0.5×ATR(14), 진입가 − 2×ATR(14))`

### E2 — 신고가 돌파 (breakout)
> 조정 없이 힘으로 뚫는 종목 추종. 손익비형 규칙 (승률 낮고 익절 큼).

- 조건:
  1. 당일 가격이 직전 20일 최고가 돌파
  2. 당일 거래량(돌파 시점 환산) ≥ 20일 평균의 1.5배
  3. 돌파 전 5일간 고가-저가 범위가 수축(변동성 수축) — ATR 5일 평균 < ATR 20일 평균
- 진입: 돌파가 + 0.2% 지정가 (추격 금지 — 돌파가 대비 +1.5% 넘으면 포기)
- 초기 손절: 돌파 기준가(직전 20일 고가) − 1×ATR(14)

두 규칙은 신호·성적을 분리 집계한다 (`rule: E1|E2` 태그). 한 종목에 동시 신호면 E1 우선.

## 3. 포지션 사이징 (1% 리스크 고정)

```
리스크 금액   = 자본(KRW 환산) × 1%
주당 리스크   = 진입가 − 초기 손절가   (USD)
수량         = floor(리스크 금액 ÷ (주당 리스크 × 환율))
```

- 상한: 한 포지션의 매입금액 ≤ 자본의 20% (손절이 촘촘해서 수량이 커지는 경우 캡)
- 수량이 1주 미만이면 진입 포기 (소수점 주문 지원 여부는 API 스펙 확인 후 결정)
- 자본은 **매월 1일 KRW 환산 평가액으로 리셋** — 매 거래마다 재계산하면 복리 변동이 심해짐

## 4. 청산 규칙 (이익을 키우는 쪽이 핵심)

1. **초기 손절 (−1R)**: 진입과 동시에 확정. 이후 아래로 내리는 것 절대 금지
2. **+1R 도달 시**: 보유량의 50% 익절 + 남은 물량 손절가를 본전으로 이동
   → 이 시점부터 해당 거래의 최악 결과는 +0.5R (심리적으로 트레일링을 버티게 해주는 장치)
3. **트레일링 스톱 (남은 50%)**: `max(직전 트레일 값, 종가 − 3×ATR(14))` — 샹들리에 방식, 올라가기만 함. 종가 기준 이탈 시 다음 기회에 시장가 청산
4. **시간 청산**: 진입 후 15거래일 내 +1R 미도달 시 종가 청산 (자본 회전율 확보 — 80R/년은 돈이 놀면 불가능)
5. **강제 청산**: 보유 중 실적발표를 만나게 되는 경우 D-2에 전량 청산 (진입 필터를 통과했어도 보유가 길어지면 발생)

### 스톱 실행 방식 (중요한 기술 제약)
토스 Open API에 서버측 스톱(stop-loss) 주문이 있는지 Phase 0에서 확인 필요.
- 없다면: 엔진이 장중 30~60초 폴링으로 감시 → 손절가 터치 시 시장가 매도
- 이 경우 **프로그램 다운 = 스톱 부재**를 의미하므로, 미국장 시간(23:30~06:00 KST) 동안 24시간 서버(홈서버/클라우드) 상시 구동이 전제 조건. 엔진 헬스체크 + 다운 시 알림 필수

## 5. 포트폴리오 리스크 규칙 (RiskManager 설정값)

| 규칙 | 값 | 근거 |
|------|-----|------|
| 동시 보유 포지션 | 최대 5 | 오픈 리스크 총합 ≤ 5R |
| 오픈 리스크 총합 | ≤ 5% (본전 스톱 이동분은 0으로 계산) | 최악의 하루 갭에도 -5% 수준 |
| 동일 섹터 동시 보유 | 최대 2 | 반도체 3종목은 사실상 한 포지션 |
| 일일 신규 진입 | 최대 2 | 과잉거래 방지 |
| 월간 손실 한도 | −8% 도달 시 당월 신규 진입 중단 | 킬스위치 연동 |
| 연속 손실 | 5연패 시 3거래일 정지 + 규칙 리뷰 | 시장 국면 vs 규칙 결함 판별 시간 |

## 6. 실행 프로세스 (엔진과의 연결)

스윙 규칙은 두 개의 사이클로 돈다:

```
[EOD 배치 — 미국장 마감 후 (07:00 KST경)]
  일봉 수집 → 지표 계산(SMA·ATR·RSI·신고가·거래량비)
  → Track B 스크리닝 → E1/E2 사전조건 평가
  → "내일 감시 목록" 생성 (종목, 트리거 가격, 손절가, 수량까지 미리 계산)

[장중 루프 — 23:30~06:00 KST, 30~60초 폴링]
  감시 목록의 트리거 가격 도달 → RiskManager 검증 → 진입 주문
  보유 포지션의 손절/트레일/+1R 가격 감시 → 청산 주문
```

- 판단(지표 계산·수량 산정)은 전부 EOD에 끝내고, 장중에는 **가격 비교와 주문만** 한다 — 장중 로직이 단순할수록 사고가 없다
- architecture.md의 규칙 YAML 스키마는 지표 조건(`sma`, `atr`, `rsi`, `high_20d`, `vol_ratio`)과 트리거/사이징 필드를 갖도록 확장 (requirements.md의 단순 가격 조건 4종은 이 스키마의 부분집합)

## 7. 검증 계획과 승격 기준

측정 지표 (모든 거래를 R 단위로 기록):
- 기대값(R/거래), 승률, 평균 손익비, Profit Factor, 최대 드로다운, 월간 R — **트랙별(A/B)·규칙별(E1/E2) 분리 집계**

단계별 게이트:
| 단계 | 기간 | 통과 기준 |
|------|------|-----------|
| 리플레이 검증 (지표 계산 확인) | 과거 일봉 3~6개월 | 신호가 의도대로 발생하는지 육안 확인 |
| dry-run | 4주+, 30거래+ | 기대값 ≥ +0.2R, 규칙 위반(수동 개입 포함) 0건 |
| 소액 실탄 | 4주 | dry-run과 실거래 결과 괴리 ≤ 슬리피지 설명 가능 수준 |
| 정상 운용 | — | 이후 월 단위 리뷰, 기대값 2개월 연속 음수면 dry-run으로 강등 |

**규칙 수정 원칙**: 운용 중 즉흥 수정 금지. 수정은 월간 리뷰에서만, 한 번에 한 파라미터만, 수정 이력은 설정 이력에 기록 (무엇이 성과를 바꿨는지 추적 가능해야 함).

## 8. 규칙 스키마 예시 (v0.2 — 엔진 구현 목표)

```yaml
strategy:
  capital_reset: monthly
  risk_per_trade: 0.01
  market_filter: { symbol: SPY, above_sma: 50 }

rules:
  - name: E1-pullback
    track: A
    universe: watchlist          # Track B는 universe: screener
    preconditions:               # EOD 평가
      - { indicator: close_above_sma, period: 50 }
      - { indicator: sma_rising, period: 50 }
      - { indicator: near_sma, period: 20, tolerance: 0.02 }
      - { indicator: rsi_between, period: 14, min: 35, max: 55 }
    trigger:                     # 장중 평가
      type: break_prev_high
    entry: { order: limit, offset: 0.001 }
    stop:  { type: swing_low_atr, lookback: 10, atr_mult: 2.0 }
    exits:
      - { at_r: 1.0, action: sell_ratio, ratio: 0.5, then: move_stop_breakeven }
      - { type: chandelier, atr_mult: 3.0 }
      - { type: time_stop, days: 15 }
      - { type: earnings_guard, days_before: 2 }
```

## 9. 사용자가 확정해줘야 할 것 (다음 스텝)

1. **Track A 관심종목 10~15개 확정** (위 §1 기준으로 후보를 뽑아오면 같이 다듬는 방식도 가능)
2. **운용 자본 규모** — 1% 리스크로 수량이 1주 이상 나오는지(사이징 실효성) 확인에 필요
3. 실적발표 일정 데이터 소스 확정 (토스 API 제공 여부 → 없으면 무료 캘린더 API 연동)
4. 24시간 구동 환경 (홈서버 vs 클라우드 VM) — 스톱 감시의 전제 조건
