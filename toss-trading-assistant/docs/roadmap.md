# 개발 로드맵

원칙: **조회 → 기록 → 판단 → (dry-run) 주문 → 실주문** 순서. 각 단계는 그 자체로 쓸모 있는 결과물을 낸다.
돈이 나가는 코드는 마지막에, 가장 작게 붙인다.

## Phase 0 — 준비 (코드 없음)

- [ ] 토스증권 Open API 신청, `CLIENT_ID`/`CLIENT_SECRET` 발급
- [ ] `openapi.json` 다운로드 → 엔드포인트·rate limit·주문 파라미터 실측 확인, requirements.md 갱신
- [ ] DART OpenAPI 인증키 발급
- [ ] 레포 초기화: `.gitignore`(.env, *.db), pre-commit(시크릿 스캔), 디렉터리 스켈레톤

## Phase 1 — 읽기 전용 대시보드 (첫 유용한 결과물)

- [ ] 인증 모듈 (토큰 발급·자동 갱신) + rate limiter
- [ ] TossClient: 잔고·시세·환율·휴장일 조회
- [ ] PortfolioService: 평가손익 계산 (원화 환산 포함) — 토스 앱과 대조 검증
- [ ] Streamlit 대시보드: 계좌 요약 + 보유종목 테이블 + 감시종목 현재가
- 완료 기준: 앱을 켜면 내 계좌 상태가 30초 내 자동 갱신으로 보인다

## Phase 2 — 설정 & 로그 기반

- [ ] config.yaml + pydantic 스키마 (감시종목·폴링 주기·리스크 한도)
- [ ] SQLite 스키마: 감사 로그·손익 스냅샷·규칙 실행 이력
- [ ] 일별 손익 스냅샷 기록 + 수익 곡선 차트
- [ ] 로그 뷰어 탭
- 완료 기준: 재시작해도 설정 유지, 어제의 손익을 오늘 볼 수 있다

## Phase 3 — 전략 엔진 (dry-run 전용)

- [ ] 규칙 스키마(YAML) + 조건 4종 (price_below/above, profit/loss_rate)
- [ ] StrategyEngine + RiskManager (킬스위치 포함) — 단위 테스트 필수
- [ ] OrderService **dry-run 경로만** 구현 (SIMULATED 로그)
- [ ] 대시보드에 전략 상태 패널 (활성 규칙·최근 트리거·거부 사유)
- 완료 기준: 최소 2주간 dry-run 운영 — SIMULATED 로그를 보고 "실주문이었어도 괜찮았는가" 검증

## Phase 4 — 실주문 연결

- [ ] 주문 API 연동 (지정가부터, 시장가는 후순위) + 체결 추적 폴링
- [ ] 대시보드에서 **수동 주문** 먼저 → 소액 실거래로 전 구간 검증
- [ ] `trading.live: true` 자동매매 개방 — 초기엔 1회 주문 금액 상한을 극소액으로
- [ ] 미체결 주문 복원·수동 취소
- 완료 기준: 규칙 1개, 최소 수량으로 자동 매수→체결→로그→포지션 갱신 전 과정 확인

## Phase 5 — 재무제표 평가

- [ ] DartClient: corp_code 매핑 + 재무제표 조회 + 캐시
- [ ] FinancialAnalyzer: 지표 7종 계산 + 등급화
- [ ] 종목 상세 패널에 재무 등급 표시, 일배치 갱신
- 완료 기준: 보유종목 전부에 대해 최신 보고서 기준 지표·등급이 보인다

## Phase 6 — 고도화 (선택)

- 지표 기반 조건 (이동평균 교차, RSI) / 시세 리플레이 백테스트
- 미국 주식 자동매매 확대 (장 시간·환율 리스크 반영)
- 알림 (체결·킬스위치 발동 시 텔레그램/이메일)
- Streamlit → FastAPI+React 전환 (필요해지면)

## 단계별 리스크 게이트

| 단계 진입 | 조건 |
|-----------|------|
| Phase 3 → 4 | dry-run 2주 이상, SIMULATED 주문 오판 0건 |
| Phase 4 소액 → 정상 운용 | 실거래 전 과정(주문→체결→로그) 10회 이상 무결점 |
| 미국 주식 자동매매 | 국내에서 1개월 이상 안정 운용 후 |
