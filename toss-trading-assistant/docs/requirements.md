# 요구사항 구체화

"보유정보·현재가·평가손익·자동매매·로그·설정·재무제표를 한 화면에서"라는 목표를
개발 가능한 단위로 쪼갠 문서. 각 기능마다 **결정해야 할 것**과 **수용 기준**을 명시한다.

---

## 0. 토스증권 Open API 개요 (2026 기준)

- Base URL: `https://openapi.tossinvest.com`, 표준 OpenAPI JSON 스펙 제공 (`/openapi-docs/latest/openapi.json`) → SDK 자동 생성 가능
- 인증: **OAuth 2.0 Client Credentials** (CLIENT_ID/SECRET → Bearer 토큰). 사용자 로그인 리다이렉트 없음
- 계좌 지정: 잔고·주문 API는 `X-Tossinvest-Account` 헤더로 계좌 선택 (다계좌 지원)
- 제공 범위: 인증 / 시세(현재가·호가·분봉·일봉) / 종목정보 / 시장정보(환율·휴장일) / 잔고·체결내역 / 주문(매수·매도·정정·취소). **국내 KRX + 미국 주식 모두 지원**
- Rate limit: 시세는 비교적 여유, **주문 API는 보수적 한도** — 초과 시 일시 차단. 클라이언트 측 rate limiter 필수
- AI 지원: 공식 `llms.txt` 제공. 커뮤니티 Agent Skill([BEOKS/tossinvest-skill](https://github.com/BEOKS/tossinvest-skill), `npx skills add BEOKS/tossinvest-skill`)로 Claude Code 등에서 API 탐색·dry-run 주문 가능 → **개발 보조 도구로 활용**
- ❗ **재무제표는 미제공** — 기업 재무 데이터는 DART OpenAPI로 별도 조달 (기능 7 참고)
- ❗ 모의투자 서버 없음(확인 필요) → dry-run을 앱 레벨에서 직접 구현해야 함

> 착수 시 첫 작업으로 `openapi.json`을 내려받아 실제 엔드포인트/파라미터를 확정할 것.
> 위 요약과 다른 부분이 있으면 이 문서를 갱신한다.

## 1. 보유정보 조회

**목표**: 계좌의 예수금, 보유종목(수량·평균단가·통화), 최근 체결내역을 조회·표시.

결정할 것:
- [ ] 대상 계좌: 단일 계좌로 시작 (설정 파일에 계좌번호 저장), 다계좌는 후순위
- [ ] 갱신 주기: 수동 새로고침 + 자동 30초 (장중), 장외에는 폴링 중단

수용 기준:
- 잔고 API 응답을 정규화한 `Position` 모델 (종목코드, 종목명, 수량, 평균단가, 통화)
- 예수금(원화/달러), 총 매입금액 표시
- API 실패 시 마지막 성공 스냅샷 + "N분 전 데이터" 표기 (빈 화면 금지)

## 2. 현재가 조회

**목표**: 보유종목 + 감시종목(watchlist)의 현재가·등락률 실시간 표시.

결정할 것:
- [ ] 폴링 주기: 감시종목 수 × 주기가 rate limit 안에 들도록 계산 (기본 5~10초, 설정 가능)
- [ ] 미국 주식: 정규장/프리·애프터 구분 표시 여부

수용 기준:
- 종목별 현재가, 전일대비, 등락률, 마지막 갱신 시각
- 휴장일·장 마감 시 폴링 자동 중단 (시장정보 API의 휴장일 데이터 활용)
- 시세 캐시: 같은 종목을 UI와 전략 엔진이 각각 호출하지 않도록 단일 수집기에서 공유

## 3. 평가손익 계산

**목표**: 종목별·계좌 전체의 평가금액, 평가손익, 수익률 표시.

계산 규칙 (직접 구현):
- 종목 평가금액 = 수량 × 현재가
- 평가손익 = 평가금액 − (수량 × 평균단가), 수익률 = 손익 / 매입금액
- 미국 주식: USD 기준 손익 + 시장정보 API 환율로 **원화 환산 손익** 병기
- 실현손익: 체결내역 기반 별도 집계 (일/월 단위)

수용 기준: 토스 앱 화면과 대조해 오차 원인(수수료·환율 시점)을 설명할 수 있을 것.

## 4. 자동매수/매도 (전략 엔진)

**목표**: 사용자가 정의한 조건이 충족되면 주문을 생성한다. **가장 위험한 기능이므로 안전장치가 스펙의 절반.**

### 4-1. 전략(규칙) 정의 — MVP 범위
선언적 규칙으로 시작 (코드가 아닌 설정으로 표현):

```yaml
rules:
  - name: "삼성전자 물타기"
    symbol: "005930"
    condition: { type: price_below, value: 62000 }
    action:   { side: buy, order_type: limit, price: 61900, qty: 10 }
    max_executions: 1          # 조건 재충족 시 반복 실행 방지
    active: true
  - name: "익절"
    symbol: "005930"
    condition: { type: profit_rate_above, value: 0.10 }   # 보유 수익률 10% 이상
    action:   { side: sell, order_type: market, qty_ratio: 0.5 }
```

- MVP 조건 타입: `price_below` / `price_above` / `profit_rate_above` / `loss_rate_below`
- 2단계: 이동평균 교차, RSI 등 지표 기반 (분봉·일봉 API로 계산)
- 조건-액션 1:1, 실행 후 규칙 비활성화(또는 카운트 차감)가 기본

### 4-2. 주문 실행 안전장치 (필수, 협상 불가)
- **dry-run 기본값**: 전역 `trading.live: false`면 주문 API를 아예 호출하지 않고 로그만 남김
- **리스크 체크 통과 후에만 주문**: 1회 주문 금액 상한 / 일일 주문 횟수 상한 / 일일 실현손실 한도 / 종목당 최대 보유 비중
- **킬스위치**: 한도 초과·연속 에러 N회 시 전략 엔진 전체 정지 + 화면에 명시
- **중복 주문 방지**: 규칙별 실행 이력 저장, 미체결 주문 존재 시 동일 규칙 재실행 금지
- **장 시간 체크**: 휴장일/장외에는 조건 평가 자체를 건너뜀
- 주문 후 체결 확인 폴링 → 미체결 시 정정/취소 정책 (MVP: 수동 취소만)

## 5. 로그 기록

**목표**: "언제 무엇을 왜 했는지" 전부 재구성 가능해야 한다.

로그 4종:
| 종류 | 내용 | 저장소 |
|------|------|--------|
| 주문 감사 로그 | 규칙명, 조건값, 시세 스냅샷, dry-run 여부, 요청/응답 원문, 체결 결과 | SQLite (영구) |
| 시세 이력 | 전략 평가에 쓰인 가격 (선택적, 용량 주의) | SQLite (보존기간 설정) |
| 앱 로그 | 시작/종료, API 에러, rate limit, 토큰 갱신 | 파일 (회전) |
| 손익 스냅샷 | 일별 평가금액·손익 (수익 곡선용) | SQLite |

수용 기준: UI에 로그 뷰어 탭 (필터: 기간·종목·종류). 시크릿(토큰·SECRET)은 절대 로그에 남기지 않음.

## 6. 설정 저장

**목표**: 전략·감시종목·리스크 한도·폴링 주기를 재시작 후에도 유지.

- 일반 설정: `config.yaml` (사람이 직접 편집 가능 + UI에서 수정 시 저장)
- **시크릿 분리**: `CLIENT_ID`/`CLIENT_SECRET`/DART 키는 `.env` 또는 OS keyring — **git에 절대 커밋 금지** (`.gitignore` + 커밋 훅으로 방어)
- 설정 스키마 검증 (pydantic): 잘못된 설정이면 기동 실패시키고 이유 출력
- 전략 규칙 변경은 이력 남김 (언제 어떤 규칙을 켰는지 — 감사 로그와 연결)

## 7. 기업 재무제표 평가

**목표**: 보유·감시종목의 재무 건전성을 지표와 등급으로 요약 표시.

- 데이터: **DART OpenAPI** — 단일회사 주요계정, 다중회사 재무제표 API (사업/반기/분기보고서). 무료, 인증키만 필요. 미국 주식은 2단계 (SEC EDGAR 또는 유료 API)
- 계산 지표(MVP): PER, PBR, ROE, 부채비율, 유동비율, 영업이익률, 매출/영업이익 YoY 성장률
  - 시가총액은 토스 시세 × 상장주식수로 계산 → 두 API의 데이터 결합 지점
- 평가: 지표별 절대 기준으로 점수화(예: 부채비율 <100% 양호) → 종합 등급(A~E). 업종 상대평가는 후순위
- 갱신: 분기 1회 수준 → **일배치 or 수동 갱신 + 로컬 캐시** (실시간 불필요)
- UI: 종목 상세 패널에 지표 테이블 + 등급, "최신 보고서 기준일" 명시

## 8. 한 화면 (대시보드) 요구사항

- 레이아웃: ① 계좌 요약(총자산·손익) ② 보유종목 테이블(현재가·손익·재무등급) ③ 감시종목 ④ 전략 상태(활성 규칙·최근 실행·킬스위치 상태) ⑤ 로그 뷰어 ⑥ 설정
- **live/dry-run 모드가 화면 최상단에 항상 보일 것** (실주문 모드임을 모르고 켜두는 사고 방지)
- 단일 사용자·로컬 실행 전제 (외부 노출 없음 — 노출 시 인증 필수)

## 9. 비기능 요구사항

- Rate limit 준수: 전역 rate limiter (시세/주문 별도 버킷), 429 응답 시 지수 백오프
- 토큰 수명 관리: 만료 전 자동 갱신, 갱신 실패 시 조회는 캐시로 버티고 주문은 중단
- 장애 격리: 시세 조회 실패가 주문 모듈을 오작동시키지 않을 것 (모듈 간 명시적 상태 전달)
- 시간대: 국내(KST)·미국(ET) 장 시간을 UTC 기준으로 내부 통일 후 표시만 로컬화
